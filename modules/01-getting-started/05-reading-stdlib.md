# 1.5 — Reading the Source

Zig 0.17.0 has no complete API reference. The autogenerated docs are patchy, and
every blog post you find was written for 0.13–0.15 and names functions that no
longer exist. The standard library source **is** the documentation, it is plain
readable Zig, and it is already on your disk.

This lesson makes that a reflex instead of a last resort.

## Set the path once

```sh
export ZSTD=$(zig env | awk -F'"' '/std_dir/{print $2}')
echo $ZSTD
```

```
/opt/homebrew/Cellar/zig/0.17.0/lib/zig/std
```

Put that `export` in your shell profile. Everything below assumes `$ZSTD`.

## The naming convention tells you the filename

Zig's stdlib layout is mechanical, which makes guessing reliable:

| Convention | Means | Example |
|---|---|---|
| `Capitalized.zig` | the file **is** a type | `Io/File.zig` → `std.Io.File` |
| `lowercase.zig` | a namespace of functions | `fmt.zig` → `std.fmt.*` |
| `Capitalized/` directory | that type's submodules | `Io/` → `std.Io.*` |

So `std.Io.File.stdout` lives in `$ZSTD/Io/File.zig`. Confirm:

```sh
grep -n "pub fn stdout" $ZSTD/Io/File.zig
```

```
/opt/homebrew/Cellar/zig/0.17.0/lib/zig/std/Io/File.zig:91:pub fn stdout() File {
```

## A real lookup, start to finish

**Question:** I want to print a horizontal rule — a repeated character — and I
want to build it in memory, not write it to a file. What does 0.17 offer?

**Step 1 — guess a keyword and list matching methods.** A repeated byte is a
"splat" in Zig's vocabulary (worth knowing); if that guess failed I'd try
`repeat`, `fill`, or `writeByteNTimes`:

```sh
grep -o "pub fn [a-zA-Z0-9_]*" $ZSTD/Io/Writer.zig | sed 's/pub fn //' | grep -i splat
```

```
countSplat
writeSplat
writeSplatHeader
writeSplatHeaderLimit
writeSplatAll
splatByteAll
splatBytePreserve
splatByte
splatBytesAll
splatBytes
```

`splatByteAll` reads like what I want.

**Step 2 — read its signature.**

```sh
grep -n "pub fn splatByteAll" -A 4 $ZSTD/Io/Writer.zig
```

```
859:pub fn splatByteAll(w: *Writer, byte: u8, n: usize) Error!void {
860:    var remaining: usize = n;
861:    while (remaining > 0) remaining -= try w.splatByte(byte, remaining);
862:}
```

`(w: *Writer, byte: u8, n: usize)` — so `w.splatByteAll('=', 12)`. The `All`
suffix (a convention worth learning) means it loops until everything is written,
versus `splatByte` which may write fewer.

**Step 3 — find a Writer with no file behind it.**

```sh
grep -n "pub fn fixed" -A 3 $ZSTD/Io/Writer.zig
```

```
125:pub fn fixed(buffer: []u8) Writer {
126-    return .{
127-        .vtable = &.{
128-            .drain = fixedDrain,
```

`fixed(buffer)` takes only a buffer — no `io`, no file. Note it returns a
`Writer` directly, so there is **no `.interface` field to reach through** here,
unlike a `File.Writer`.

**Step 4 — get the bytes back out.**

```sh
grep -n "pub fn buffered" -A 3 $ZSTD/Io/Writer.zig
```

```
155:pub fn buffered(w: *const Writer) []u8 {
156:    return w.buffer[0..w.end];
157:}
```

**Step 5 — write it.** Four greps, no guessing, no internet:

```zig
const std = @import("std");

pub fn main() !void {
    var mem: [128]u8 = undefined;
    var w = std.Io.Writer.fixed(&mem);

    try w.splatByteAll('=', 12);
    try w.writeByte('\n');
    try w.writeAll("found by grep\n");
    try w.splatByteAll('=', 12);

    std.debug.print("{s}\n", .{w.buffered()});
    std.debug.print("{d} bytes written\n", .{w.buffered().len});
}
```

```
============
found by grep
============
39 bytes written
```

## Reading the source as a habit

A few things that make stdlib files faster to read:

| Look for | Tells you |
|---|---|
| `pub const Error = ...` near the top | every error the type can return |
| `//!` at line 1 | the file's own module-level summary |
| `///` above a function | that function's real doc comment |
| `test "..."` blocks | **usage examples that are guaranteed to compile** |
| `pub const empty` / `pub const init` | how to construct the type |

That fourth row is the underrated one. The stdlib's own tests are working
example code for the exact version you are running:

```sh
grep -c "^test " $ZSTD/Io/Writer.zig
```

```
28
```

## Translating old tutorial code

When you hit code that won't compile, the workflow is mechanical:

1. **Grep for the name.** `grep -rn "getStdOut" $ZSTD` → no hits → it's gone.
2. **Grep for the concept.** `grep -rn "pub fn stdout" $ZSTD` → `Io/File.zig`.
3. **List the type's methods** (recipe 1) to find the modern equivalent.
4. **Read the signature** (recipe 2) for the new argument list.

The renames you will hit most in module 02 and beyond:

| Tutorial says | Grep for | 0.17.0 |
|---|---|---|
| `std.io.getStdOut()` | `pub fn stdout` | `std.Io.File.stdout()` |
| `std.fs.File` | `Io/File.zig` | `std.Io.File` |
| `std.fs.cwd()` | `pub fn cwd` | `std.Io.Dir.cwd()` |
| `ArrayList.init(gpa)` | `pub const empty` | `var l: std.ArrayList(T) = .empty;` |
| `GeneralPurposeAllocator` | `DebugAllocator` | `std.heap.DebugAllocator(.{})` |

When a lesson in this course and your memory disagree, grep settles it. The
source on your disk is the only authority that matches your compiler.
