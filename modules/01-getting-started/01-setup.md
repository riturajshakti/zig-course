# 1.1 — Setup & Verify

## Check your toolchain

```sh
zig version
```

```
0.17.0
```

If that says anything other than `0.17.0`, stop — half the code in this course
will fail against an older stdlib.

## The four commands you will actually use

| Command | Does | Writes a binary? |
|---|---|---|
| `zig run f.zig` | compile + execute immediately | no (cached) |
| `zig test f.zig` | compile + run every `test {}` block | no |
| `zig build-exe f.zig` | compile to `./f` | yes |
| `zig fmt f.zig` | reformat in place | n/a |

## `zig run`

```zig
const std = @import("std");

pub fn main() void {
    const b = @import("builtin");
    std.debug.print("zig {f}\n", .{b.zig_version});
    std.debug.print("arch {t} os {t} mode {t}\n", .{ b.cpu.arch, b.os.tag, b.mode });
}
```

```sh
zig run version.zig
```

```
zig 0.17.0
arch aarch64 os macos mode debug
```

`@import("builtin")` is generated by the compiler for your exact target — it is
not a file on disk. `{f}` calls a type's own `format` method, `{t}` prints an
enum's tag name. More on specifiers in lesson 1.3.

## `zig test`

Tests live in the same file as the code. No separate test directory, no test runner to install.

```zig
const std = @import("std");

fn double(x: i32) i32 {
    return x * 2;
}

test "double works" {
    try std.testing.expectEqual(@as(i32, 8), double(4));
}

test "slices compare" {
    try std.testing.expectEqualStrings("zig", "zig");
}
```

```sh
zig test double.zig
```

```
1/2 double.test.double works...OK
2/2 double.test.slices compare...OK
All 2 tests passed.
```

Note there is no `main` in that file. `zig test` builds its own entry point.

## `zig fmt`

There is one official style and no config file. Before:

```zig
const std=@import("std");
pub fn main() void {
std.debug.print(   "hi\n",.{}  );
}
```

```sh
zig fmt ugly.zig
```

Prints nothing on success, rewrites the file in place with no backup:

```zig
const std = @import("std");
pub fn main() void {
    std.debug.print("hi\n", .{});
}
```

| Variant | Behavior |
|---|---|
| `zig fmt f.zig` | rewrites in place, silent on success |
| `zig fmt .` | rewrites every `.zig` under the current directory |
| `zig fmt --check f.zig` | rewrites nothing; prints offending filenames, exits `1` |

```sh
zig fmt --check ugly.zig
```

```
ugly.zig
```

Exit code `1`. That is the CI-friendly form.

## Unused variables are compile errors

This bites everyone on day one:

```zig
const std = @import("std");

pub fn main() void {
    const x = 42;
    std.debug.print("hi\n", .{});
}
```

```
unused.zig:4:11: error: unused local constant
    const x = 42;
          ^
```

The escape hatch is a discard:

```zig
const std = @import("std");

pub fn main() void {
    const x = 42;
    _ = x;
    std.debug.print("hi\n", .{});
}
```

```
hi
```

`_ = x;` works for unused parameters and unused results too. Zig has no
`-Wno-unused`; this is not a warning you can turn off.

## Where the standard library lives

You will read it constantly. Find it once:

```sh
zig env
```

```
.{
    .zig_exe = "/opt/homebrew/Cellar/zig/0.17.0/bin/zig",
    .lib_dir = "/opt/homebrew/Cellar/zig/0.17.0/lib/zig",
    .std_dir = "/opt/homebrew/Cellar/zig/0.17.0/lib/zig/std",
    .global_cache_dir = "/Users/raj/.cache/zig",
    .version = "0.17.0",
    .target = "aarch64-macos.26.5.2...26.5.2-none",
```

Save that path — lesson 1.5 is entirely about reading it:

```sh
export ZSTD=$(zig env | awk -F'"' '/std_dir/{print $2}')
ls $ZSTD/Io
```
